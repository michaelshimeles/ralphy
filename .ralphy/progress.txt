## Task: Implement record_agent_result() function

### Implementation Summary

Implemented the `record_agent_result()` function in ralphy.sh that aggregates metrics by engine for multi-engine support.

### Changes Made

1. **Added Engine Tracking Data Structures** (ralphy.sh:88-94)
   - `ENGINE_AGENT_COUNT` - Tracks total agents per engine
   - `ENGINE_SUCCESS` - Tracks success count per engine
   - `ENGINE_FAILURES` - Tracks failure count per engine
   - `ENGINE_COSTS` - Aggregates total cost per engine
   - `ENGINE_TOKENS_IN` - Aggregates input tokens per engine
   - `ENGINE_TOKENS_OUT` - Aggregates output tokens per engine
   - `ENGINE_DURATION_MS` - Aggregates duration per engine (for engines that report it)

2. **Implemented record_agent_result() Function** (ralphy.sh:1700-1774)
   - Function signature: `record_agent_result <engine> <cost> <tokens_in> <tokens_out> <duration_ms> <success>`
   - Validates required engine parameter
   - Auto-initializes metrics for new engines
   - Aggregates all metrics correctly:
     - Increments agent count
     - Tracks success/failure counts
     - Accumulates tokens (in/out)
     - Accumulates cost (using bc when available)
     - Accumulates duration (when provided)
   - Includes debug logging for visibility

3. **Created Comprehensive Test Suite** (test_record_agent_result.sh)
   - 8 test suites covering:
     - Basic functionality
     - Multiple agents per engine
     - Multiple engines
     - Success/failure tracking
     - Duration tracking
     - Edge cases (zero values)
     - Error handling (missing parameters)
     - Large numbers handling
   - Tests validate all aggregation logic
   - Provides clear pass/fail output

### Technical Notes

- **Bash 4.0+ Required**: The implementation uses associative arrays (declare -A), which require bash 4.0 or higher
- **Cost Precision**: Cost aggregation uses `bc` for decimal precision. Falls back gracefully if bc is not available
- **Backward Compatible**: New associative arrays don't affect existing functionality
- **Thread-safe Design**: Each engine's metrics are independent and can be updated safely

### Usage Example

```bash
# Record a successful agent execution
record_agent_result "claude" "0.0015" 1000 500 0 1

# Record a failed agent execution with duration
record_agent_result "cursor" "0.0020" 2000 1000 5000 0

# Access aggregated metrics
echo "Claude success count: ${ENGINE_SUCCESS[claude]}"
echo "Claude total cost: ${ENGINE_COSTS[claude]}"
echo "Claude total input tokens: ${ENGINE_TOKENS_IN[claude]}"
```

## Task: Call record_agent_result() after each agent completes

### Implementation Summary

Integrated calls to `record_agent_result()` throughout ralphy.sh to track metrics after each agent completes execution, both in parallel and sequential modes.

### Changes Made

1. **Parallel Agent Execution - Success Path** (ralphy.sh:2233-2251)
   - Added extraction of `actual_cost` from parsed result (line 2183)
   - Added cost and duration calculation logic (lines 2233-2248)
   - Extracts duration from `duration:XXX` format for Cursor/Droid engines
   - Calculates estimated cost using `calculate_cost()` when actual cost not provided
   - Calls `record_agent_result()` with engine, cost, tokens, duration, and success=1 (line 2251)

2. **Parallel Agent Execution - Failure Paths**
   - **No-commit failure path** (lines 2197-2213)
     - Extracts tokens and cost even when commit check fails
     - Calls `record_agent_result()` with success=0 before cleanup
   - **General failure path** (lines 2262-2263)
     - Calls `record_agent_result()` with zero metrics when agent execution fails
     - Ensures all failures are tracked

3. **Sequential Task Execution - Success Path** (ralphy.sh:1941-1959)
   - Added cost and duration calculation after task completion
   - Extracts duration from `actual_cost` if present
   - Calculates estimated cost if not provided by engine
   - Calls `record_agent_result()` with success=1 after task is marked complete

4. **Sequential Task Execution - Failure Paths**
   - **Empty response failure** (lines 1863-1864)
     - Calls `record_agent_result()` with zero metrics after max retries
   - **API error failure** (lines 1881-1882)
     - Calls `record_agent_result()` with zero metrics after max retries
   - **General retry exhaustion** (lines 1982-1983)
     - Calls `record_agent_result()` with zero metrics when all retries fail

5. **Created Integration Test Suite** (test_agent_result_calls.sh)
   - Tests that `record_agent_result()` is called in all execution paths
   - Validates parameters (engine, cost, tokens, duration, success status)
   - Verifies cost calculation and duration extraction logic
   - All 12 tests pass successfully

### Technical Implementation Details

**Cost Handling:**
- OpenCode: Uses actual cost from `.part.cost` field
- Claude/Qwen: Calculates estimated cost using token counts
- All engines: Falls back to `calculate_cost()` if actual cost not available

**Duration Handling:**
- Cursor: Extracts duration from `duration:XXX` format in actual_cost
- Droid: Extracts duration from completion event
- Claude/OpenCode/Qwen: Duration set to 0 (not provided)

**Success Status:**
- Success = "1": Task completed with commits/changes
- Success = "0": Task failed due to errors, empty response, or no commits

1. `run_parallel_agent()` success: ralphy.sh:2251
2. `run_parallel_agent()` no-commit failure: ralphy.sh:2213
3. `run_parallel_agent()` general failure: ralphy.sh:2263
4. `run_single_task()` success: ralphy.sh:1959
5. `run_single_task()` empty response failure: ralphy.sh:1864
6. `run_single_task()` API error failure: ralphy.sh:1882
7. `run_single_task()` general failure: ralphy.sh:1983
